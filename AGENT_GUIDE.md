# Using ui-lib as an agent

This file is for an agent that **consumes** the library (builds screens with it). If you are changing the library itself, read `AGENTS.md` instead.

## 1. Fastest path: ask the MCP server

Add it to your MCP client:

```json
{
  "mcpServers": {
    "ui-lib": {
      "command": "bun",
      "args": ["/absolute/path/to/ui-lib/mcp/server.mjs"]
    }
  }
}
```

| Tool              | Use it to                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `get_guidelines`  | Read the rules first (always)                                                                |
| `list_components` | See what exists, optionally by category                                                      |
| `get_component`   | Props with allowed values, what HTML it renders, composition, things to avoid, accessibility |
| `get_examples`    | Copy-paste usage                                                                             |
| `search_tokens`   | Find a CSS variable by meaning (`focus`, `border`, `danger`, `space`)                        |
| `search_icons`    | Find an icon by name, category or tag                                                        |
| `get_icon`        | Import line and usage for one icon                                                           |

## 2. Without MCP: read the files

- `/llms.txt`: short index
- `/llms-full.txt`: all components and tokens in one Markdown file
- `/agent/manifest.json` and `/agent/tokens.json`: same content as JSON
- `/agent/icons.json`: every available icon with its component name and tags

All of them are generated by `bun run agent-docs` from the real types, TSDoc and tokens, so they match the code.

## 3. Rules

1. **HTML first.** Use the component for the job: `Heading` for headings, `Text` for body text, `Link` for navigation, `Button` for actions. Never `div` with `onClick`.
2. **Semantic tokens only.** `--color-card`, `--color-primary-foreground`, `--space-4`, `--text-body-size`. Never `--primitive-*`, hex colors, pixel values or font names.
3. **Every control has an accessible name.** `Field label`, the component's own `label` or `legend`, or `aria-label`.
4. **Heading order.** One `h1` per page, no skipped levels. Change the look with `size`, not the level.
5. **Import from `@/ui`.** `import { Button, Stack, Heading } from "@/ui";`
6. **Do not rebuild behavior.** Modal, Select, Tabs, Tooltip, Checkbox, Radio, Switch and Button come from Base UI; do not recreate focus, keyboard or ARIA handling.
7. **Tooltips are optional extras.** Never put required information only in a tooltip.
8. **Icons are named components.** Import them from `@/ui` (`import { CheckIcon, ArrowRightIcon } from "@/ui";`). Never draw an `<svg>` or write a `<path>` by hand. Pick the size with `size` (`xs` 12, `sm` 16, `md` 20, `lg` 24, `xl` 32) and use `weight="fill"` only for an active or selected state. Icon-only controls still need an accessible name.

## 4. Example: a small form

```tsx
import { Button, Field, Heading, Input, Stack, Textarea } from "@/ui";

export function Contact() {
  return (
    <form>
      <Stack gap="4">
        <Heading as="h2">Contact us</Heading>
        <Field label="Email">
          <Input type="email" name="email" autoComplete="email" required />
        </Field>
        <Field label="Message" description="Up to 500 characters.">
          <Textarea name="message" rows={4} />
        </Field>
        <Button type="submit">Send</Button>
      </Stack>
    </form>
  );
}
```

## 5. Light and dark

Set `data-theme="light"` or `"dark"` on `<html>`. Without it the OS preference applies. Components need no changes: they only read semantic tokens.

## 6. Links and navigation

Wrap the app once in `<LinkProvider component={NextLink}>` (see `src/app/providers.tsx`). Then `Link`, `Button` with `href`, `Menu` link items, `Breadcrumb` and `Pagination` all render with `next/link`. Never pass a `render` prop per link. Use `Button` with `href` for a link that looks like a button, `Button` with `onClick` for actions that do not navigate, and `Link` for navigation as inline text. `href` decides the element, so do not render a button with `onClick` and `router.push` to navigate. `Pagination` takes `hrefTemplate` (a string with `{page}`), not a function, so it works from Server Components.
