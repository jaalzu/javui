# Using ui-lib as an agent

This file is for an agent that **consumes** the library (builds screens with it). If you are changing the library itself, read `AGENTS.md` instead.

## 1. Fastest path: ask the MCP server

Add it to your MCP client:

```json
{
  "mcpServers": {
    "ui-lib": {
      "command": "bun",
      "args": ["/absolute/path/to/ui-lib/mcp/server.mjs"]
    }
  }
}
```

| Tool              | Use it to                                                                                    |
| ----------------- | -------------------------------------------------------------------------------------------- |
| `get_guidelines`  | Read the rules first (always)                                                                |
| `list_components` | See what exists, optionally by category                                                      |
| `get_component`   | Props with allowed values, what HTML it renders, composition, things to avoid, accessibility |
| `get_examples`    | Copy-paste usage                                                                             |
| `search_tokens`   | Find a CSS variable by meaning (`focus`, `border`, `danger`, `space`)                        |
| `search_icons`    | Find an icon by name, category or tag                                                        |
| `get_icon`        | Import line and usage for one icon                                                           |

## 2. Without MCP: read the files

- `/llms.txt`: short index
- `/llms-full.txt`: all components and tokens in one Markdown file
- `/agent/manifest.json` and `/agent/tokens.json`: same content as JSON
- `/agent/icons.json`: every available icon with its component name and tags

All of them are generated by `bun run agent-docs` from the real types, TSDoc and tokens, so they match the code.

## 3. Rules

1. **HTML first.** Use the component for the job: `Heading` for headings, `Text` for body text, `Link` for navigation, `Button` for actions. Never `div` with `onClick`.
2. **Semantic tokens only.** `--color-card`, `--color-primary-foreground`, `--space-4`, `--text-body-size`. Never `--primitive-*`, hex colors, pixel values or font names.
3. **Every control has an accessible name.** `Field label`, the component's own `label` or `legend`, or `aria-label`.
4. **Heading order.** One `h1` per page, no skipped levels. Change the look with `size`, not the level.
5. **Import from the package.** `import { Button, Stack, Heading } from "@javui/ui";`; import `CodeBlock` only from `@javui/ui/server`. Never use `@/ui`.
6. **Limit page width with CSS.** Use `max-width` with `--container-*` and center with `margin-inline: auto`.
7. **Do not rebuild behavior.** Modal, Select, Tabs, Tooltip, Checkbox, Radio, Switch and Button come from Base UI; do not recreate focus, keyboard or ARIA handling.
7. **Tooltips are optional extras.** Never put required information only in a tooltip.
8. **Icons are named components.** Import them from `@javui/ui` (`import { CheckIcon, ArrowRightIcon } from "@javui/ui";`). Never draw an `<svg>` or write a `<path>` by hand. Pick the size with `size` (`xs` 12, `sm` 16, `md` 20, `lg` 24, `xl` 32) and use `weight="fill"` only for an active or selected state. Icon-only controls still need an accessible name.

## 4. Example: a small form

Empty states should vary their content within a page to avoid redundancy for screen readers.

```tsx
import { Button, Field, Heading, Input, Stack, Textarea } from "@javui/ui";

export function Contact() {
  return (
    <form>
      <Stack gap="4">
        <Heading as="h2">Contact us</Heading>
        <Field label="Email">
          <Input type="email" name="email" autoComplete="email" required />
        </Field>
        <Field label="Message" description="Up to 500 characters.">
          <Textarea name="message" rows={4} />
        </Field>
        <Button type="submit">Send</Button>
      </Stack>
    </form>
  );
}
```

## 5. Light and dark

Set `data-theme="light"` or `"dark"` on `<html>`. Without it the OS preference applies. Components need no changes: they only read semantic tokens.

## 6. Links and navigation

In Next App Router, mount `LinkProvider` inside a client `Providers` component; a Server Component cannot pass the `next/link` function across the boundary. Copy `playgrounds/next/app/providers.tsx`. Then `Link`, `Button` with `href`, `Menu` link items, `Breadcrumb` and `Pagination` all render with `next/link`. Never pass a `render` prop per link.

## 7. Server Components and performance

Static primitives such as `Text`, `Heading`, `Stack`, `Grid`, `Container` and `Card` are intended
to work from Server Components. Interactive controls and components that use state, effects,
context, browser APIs or Base UI behavior require a client boundary. `CodeBlock` is server-only: import it from `@javui/ui/server`, not from a client component. The package has no Next-specific directives, so it works with or without `cacheComponents`.

Use `useTransition`, memoization and list virtualization only when a measured interaction needs
them. Virtualized lists must preserve keyboard navigation, accessible names and the semantics of
the visible collection. Do not add performance abstractions to static primitives without a
measured benefit.

## 8. Styling hooks

Component custom properties are the supported visual extension points. Prefer documented hooks
such as `--card-spacing` or `--alert-tone` over selectors that reach into component internals.
Hooks default to semantic tokens; internal variables such as generated responsive variables and
`--icon-size` are not public API.

## 9. Layout utilities

### Component taxonomy

The catalog separates primitives from composition patterns:

- `typography`: content primitives such as `Text`, `Heading` and `Link`.
- `layout`: structural primitives such as `Stack`, `Grid`, `Container` and `Box`.
- `patterns`: semantic/data-display utilities such as `DescriptionList` and `NameValueList`.
- `utility`: behavior-free helpers such as `VisuallyHidden`, `Icon`, `Spinner` and `Skeleton`.

`DescriptionList` is not an atom and is not a layout grid. It owns the semantic `dl`/`dt`/`dd`
relationship. `NameValueList` is a data-driven presentation pattern built on that structure.
Keep these patterns independent from page layout so they can be composed inside cards, grids or
forms without imposing a container strategy.

Global composition utilities use the `ui-` prefix and semantic tokens. Use `Container`, `Stack`,
`Grid` and `Box` when their typed API expresses the intent; use utilities for a small external
composition or a one-off modifier. Common utilities include `ui-flex`, `ui-grid`, `ui-col`,
`ui-flex-wrap`, `ui-items-center`, `ui-justify-between`, `ui-size-1-of-2`, `ui-md-size-1-of-3`,
`ui-m-4`, `ui-p-4`, `ui-max-w-md`, `ui-is-relative` and `ui-is-absolute`. Logical edge
utilities use `ms`/`me` and `ps`/`pe`; use these instead of left/right-specific rules. The
`ui-has-top-magnet` and `ui-has-bottom-magnet` utilities are reserved for adjacent card-like
surfaces that should visually connect.

`ui-is-absolute` requires a deliberate `ui-is-relative` ancestor. Prefer logical spacing classes
and layout gaps over margins between siblings. The grid fraction and order utilities are
mobile-first; visual reordering must preserve the reading order in the DOM.

## 10. Semantic lists and text overflow

Use `DescriptionList` with `DescriptionListTerm` and `DescriptionListDetails` for native `dl`/
`dt`/`dd` semantics. Use `NameValueList` for data-driven pairs; use `Table` when the content is
tabular data rather than term/description data.

Text truncation is opt-in. `Text truncate` is for one line; `Text lineClamp={2}` through `{5}`
is for direct text content only. Do not apply line clamp to a container that contains nested HTML.
`hyphenate` and the matching `ui-hyphenate` utility are also opt-in. Line clamp is not supported
in IE11, which is outside the library's browser support target.

## 11. Package and CSS entry points

Import `@javui/ui/tokens.css` (required), with optional `base.css`, `fonts.css`, `tailwind.css`, or `styles.css`.
`CodeBlock` exists only at `@javui/ui/server`. `ModalContent` requires `closeLabel`, for example
`<ModalContent title="Confirm" closeLabel="Close">...</ModalContent>`. The package has no Next-specific
directives, so it works with or without `cacheComponents`.
